# PPT/PDF → 公众号图片推文（预留实拍照片位）

配套模板在本 skill 目录的 `template/`：`render.py`（导出脚本）、`排版源稿.html`（正文排版，可编辑照片位）、`封面源稿.html`（横版900×383 + 方形500×500）、`assets/`、`photos/`。新任务时复制 `template/` 到新文件夹再改内容。

## 0. 原则
- 只用源文件里有的信息；日期、地点、人数、氛围、问答、引语、福利、截止时间等没有就不写，绝不编造。
- 照片位、二维码位只留清晰占位并标注应放什么（如「主讲老师照片 · 竖版3:4」），绝不用AI生成或伪造实拍照片/二维码。
- PPT中引用的第三方观点写成「有观点认为」，不当成讲者原话。
- 只交付本地文件，不代为发布；使用用户给定的机构名称；用用户的语言简短回复。
- 每次修订另存带时间戳的新文件夹，保留旧版本。

## 1. 读源文件
- PDF：`pdftotext` 提文字，`pdftoppm -r 110` 出逐页图；PPTX 先用 LibreOffice 转 PDF。
- 梳理结构：开场 → 人物/主办方介绍 → 各章节 → 互动/问答 → 结尾金句 → 收尾。
- 挑几页关键PPT截图作配图，标注「讲座PPT · P页码」，裁掉标题栏和边框。

## 2. 写文案
- 正文约1200–1800字，口语化但克制；每章「小标题 + 2–4句」，金句单独突出。
- 规划照片位：人物竖版3:4，现场横版，可两张并排，结尾集体合影；编号 p1…pN 并列对照表。
- 结尾可加招新模块：标题 + 一句邀请 + 320×320 二维码占位 + 「长按识别二维码」。

## 3. 排版（HTML → PNG）
- `排版源稿.html` 宽900px，内容分为若干 `.seg` 分段；品牌主色 + 2–3个浅色分区，避免背景单调。
- 照片位 `.ph` 可编辑：点击上传、拖动/缩放构图、替换/清除；「删除此框」加 `data-removed`，导出时跳过并自动收拢；有已删除列表（恢复/撤销/全部恢复）；「开启编辑」可改文字；「保存编辑后的HTML」以 base64 嵌入照片。
- 导出时自动载入 `photos/pN.jpg`、`photos/qrcode.png`。
- 封面必须贴合本次主题（用PPT主标题/主视觉），不沿用旧活动封面。
- `python3 render.py [html] [--scale 2]`：Playwright Chromium 打开（带 `?export=1`），导出整张长图 + 按分段导出（每张约≤2500px，不切断文字或照片）+ 两张封面，输出到 `成品图片/`。依赖：`pip install playwright` 和 `python -m playwright install chromium`。

## 4. 自检
- 逐张看分段图：无溢出、重叠、错字、截断；名称统一。
- 生成 `封面一览.jpg` 预览；对照照片位编号表检查。

## 5. 交付
- 先发长图或分段预览，再发 ZIP：成品图片/（长图、分段01…、两张封面）、可编辑HTML、render.py、照片位说明。无 zip 命令时用 Python `zipfile`。
- 附推荐标题 + 3–4个备选：一个稳妥版（与封面主题一致），一个问句版（更抓人）。

## 6. 用户填好照片后转PNG
- 复制最新模板文件夹到新文件夹，放入用户的HTML，运行 `python3 render.py 文件.html --scale 2`，得到1800宽高清图。
- 附件有大小限制时，长图（约20MB）单独发，分段图和封面打一个ZIP。
- 告诉用户已填几个照片位、删了几个，提醒上传公众号时不要勾选压缩。
